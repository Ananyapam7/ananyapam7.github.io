We now have two gradient routes: change the density, or move the sample. A real probabilistic program may contain both discrete draws and differentiable continuous operations. Stochastic computation graphs explain how the derivatives of those pieces fit together, and which future costs each random choice is responsible for.

Factor a computation into conditional draws \(v\sim p(v\mid\mathrm{parents})\) and deterministic operations. Differentiating the joint sampling density gives a score contribution for each stochastic node. Only costs downstream of that node need to multiply its score, since the expected product with an unaffected cost vanishes after conditioning on the appropriate predecessors. Differentiable paths contribute ordinary chain-rule terms. [BBVI](#paper-3) and [AEVB](#paper-4) can therefore appear in different parts of the same model. This is especially helpful when the model has both continuous and discrete random variables.

**Consider a discrete gate followed by a continuous computation.** Draw \(z\sim q_\phi\), compute \(h_\phi(z)\), and evaluate a cost \(c(h_\phi(z))\). There are two ways \(\phi\) changes the average cost: it changes how often each gate is chosen, and it changes the computation after a gate has been chosen. Thus

\[
\nabla_\phi\mathbb E_q[c(h_\phi(z))]
=\mathbb E_q\!\left[
c(h_\phi(z))S_\phi(z)
+\left.\nabla_\phi c(h_\phi(z))\right|_{z\;\mathrm{fixed}}
\right].
\]

The first term handles the random choice; the second is ordinary backpropagation. Ignoring the first would never teach the model which choices to make. Including unrelated costs in it would add noise without useful credit assignment.

The paper organizes these rules into a graph-based surrogate whose derivatives produce the desired estimator. This makes mixed stochastic programs easier to implement and explains where baselines can depend on earlier information.

**Its scope.** This is a framework for constructing correct gradients, not a promise that they have low variance. A long downstream sequence can give a very noisy score signal; a long differentiable path can have exploding derivatives. [NVIL](#paper-15), [RELAX](#paper-18), and the pathwise methods can be understood as improving particular pieces of this graph.

**What carries forward.** This is a general calculus for stochastic programs, not a new VI objective. It lets an implementation mix score and pathwise terms and use the graph's dependency structure to remove irrelevant learning signals.
