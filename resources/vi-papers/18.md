REBAR's control follows a particular relaxed version of the discrete cost. That may be a poor predictor when the true cost is complicated. RELAX asks whether we can learn the control itself for the sole purpose of reducing gradient variance, without requiring it to be a faithful model of the cost everywhere.

RELAX uses the same unconditional-minus-conditional correction as REBAR, with a learned differentiable function \(c_\psi\). If \(\widehat g_{\phi,\psi}\) is an unbiased estimator for each fixed \(\psi\), its mean does not depend on \(\psi\), so

\[
\nabla_\psi\operatorname{Var}(\widehat g_{\phi,\psi})=\nabla_\psi\mathbb E[\widehat g_{\phi,\psi}^2]
\]

for a scalar component. This gives a training objective for the control variate itself. REBAR starts from a relaxation of the original function. RELAX allows a learned function whose job is to make the gradient estimator less noisy.

**The auxiliary network learns how to cancel noise.** A good control need not reproduce the function value everywhere. Its purpose is to fluctuate with the original estimator so that subtraction removes noise. This differs from learning the posterior or learning the generative model: \(\psi\) controls estimator quality, while \(\phi\) controls the approximation being fitted.

For a vector gradient, the corresponding training target is its squared norm:

\[
\nabla_\psi\operatorname{tr}\operatorname{Cov}(\widehat g_{\phi,\psi})
=\nabla_\psi\mathbb E[\|\widehat g_{\phi,\psi}\|^2].
\]

The mean-gradient term disappears because the correction preserves it for every fixed choice of \(\psi\). We can therefore update the control using a sampled gradient, then continue updating the inference parameters with the corrected estimator. The paper also develops LAX for continuous variables; RELAX adds the conditional construction needed for discrete choices.

**Why more flexibility is not free.** A learned control can fit nonlinear patterns that a fixed relaxation misses, but it needs its own optimization and derivatives through the gradient estimator. Early in training it may be a poor predictor, and its extra evaluations can outweigh a variance reduction on cheap problems. The useful comparison is progress per unit of computation, not just the variance of one update. Simple paired estimators such as [ARM](#paper-20) avoid training this auxiliary network.

**What carries forward.** The general principle is to learn an auxiliary object against *estimator variance*, not model fit. Its parameters serve the optimizer, not the posterior. This separation is useful across stochastic optimization, although the training and evaluation cost may outweigh the gain.
